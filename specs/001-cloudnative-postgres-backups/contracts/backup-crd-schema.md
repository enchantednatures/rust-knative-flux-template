# CloudNativePG Backup and ScheduledBackup CRD Schema

This document describes the `Backup` and `ScheduledBackup` custom resources for managing PostgreSQL backups with the Barman Cloud Plugin.

## Backup Resource (On-Demand)

### Resource

```yaml
apiVersion: postgresql.cnpg.io/v1
kind: Backup
```

### Key Fields

#### metadata
- `name` (string, required): Backup identifier (must be unique, recommend timestamp suffix)
- `namespace` (string, optional): Kubernetes namespace (must match target cluster)

#### spec

##### method (string, required)
Backup method to use.
- **Value**: `plugin` (required for Barman Cloud Plugin)
- Legacy value `barmanObjectStore` is deprecated (CNPG 1.26+)

##### pluginConfiguration (object, required when method=plugin)
Configuration for plugin-based backups.

- `name` (string, required): Plugin identifier
  - **Value**: `barman-cloud.cloudnative-pg.io`
- `parameters` (map[string]string, required):
  - `barmanObjectName` (string, required): Name of ObjectStore CRD to use

##### cluster (object, required)
Reference to target PostgreSQL cluster.
- `name` (string, required): Name of Cluster resource to backup

##### target (string, optional)
Backup target selection.
- Options: `primary`, `prefer-standby`
- Default: `prefer-standby` (recommended - reduces load on primary)
- Use `primary` only if standby replicas are unavailable

#### status (read-only)
Populated by the operator after backup execution.

##### phase (string)
Current backup state.
- Values: `pending`, `running`, `completed`, `failed`

##### startedAt (timestamp)
RFC 3339 timestamp when backup started.

##### stoppedAt (timestamp)
RFC 3339 timestamp when backup completed or failed.

##### backupId (string)
Unique identifier for the backup (generated by Barman).

##### size (integer)
Backup size in bytes (uncompressed).

##### error (string)
Error message if backup failed.

## ScheduledBackup Resource (Automated)

### Resource

```yaml
apiVersion: postgresql.cnpg.io/v1
kind: ScheduledBackup
```

### Key Fields

#### metadata
- `name` (string, required): Schedule identifier
- `namespace` (string, optional): Kubernetes namespace (must match target cluster)

#### spec

##### schedule (string, required)
Cron expression for backup schedule.
- Format: Standard cron (minute hour day month weekday)
- Timezone: UTC
- Examples:
  - `0 2 * * *` - Daily at 2:00 AM UTC
  - `0 */6 * * *` - Every 6 hours
  - `0 0 * * 0` - Weekly on Sunday at midnight
  - `0 3 1 * *` - Monthly on 1st at 3:00 AM

##### suspend (boolean, optional)
Temporarily disable scheduled backups.
- Default: `false`
- Set to `true` to pause backups without deleting the schedule

##### method (string, required)
Backup method to use.
- **Value**: `plugin` (required for Barman Cloud Plugin)

##### pluginConfiguration (object, required when method=plugin)
Configuration for plugin-based backups.

- `name` (string, required): Plugin identifier
  - **Value**: `barman-cloud.cloudnative-pg.io`
- `parameters` (map[string]string, required):
  - `barmanObjectName` (string, required): Name of ObjectStore CRD to use

##### cluster (object, required)
Reference to target PostgreSQL cluster.
- `name` (string, required): Name of Cluster resource to backup

##### target (string, optional)
Backup target selection.
- Options: `primary`, `prefer-standby`
- Default: `prefer-standby`

##### immediate (boolean, optional)
Trigger immediate backup on schedule creation.
- Default: `false`
- Set to `true` to create first backup immediately (useful for testing)

##### backupOwnerReference (string, optional)
Owner reference strategy for created Backup objects.
- Options: `none`, `self`, `cluster`
- Default: `self`
- `self`: ScheduledBackup owns created Backups (delete schedule = delete backups)
- `cluster`: Cluster owns backups (delete cluster = delete backups)
- `none`: No owner reference (manual cleanup required)

#### status (read-only)
Populated by the operator.

##### lastScheduleTime (timestamp)
RFC 3339 timestamp of last successful backup.

##### lastBackupName (string)
Name of the most recent Backup resource created.

## Backup Lifecycle

### On-Demand Backup Flow

1. Operator receives Backup resource
2. Validates cluster exists and is healthy
3. Selects backup target (primary or standby)
4. Creates backup snapshot (via Barman Cloud Plugin)
5. Uploads base backup to object storage (referenced by ObjectStore CRD)
6. Archives WAL files continuously
7. Updates Backup status with result

### Scheduled Backup Flow

1. Operator evaluates cron schedule (every 1 minute check)
2. At scheduled time, creates new Backup resource
3. Backup resource follows on-demand flow
4. ScheduledBackup status updated with last execution
5. Old Backup resources cleaned up based on `backupOwnerReference`
6. Old backup files removed from object storage based on ObjectStore `retentionPolicy`

## Backup Types

### Full Base Backup
- Complete copy of database files at a point in time
- Created by `Backup` or `ScheduledBackup` resources
- Stored in object storage: `s3://bucket/path/base/<backupId>/`
- Includes data files, configuration, and metadata
- Compressed according to ObjectStore `data.compression` setting

### WAL Archive (Continuous)
- Write-Ahead Log files archived continuously (not scheduled)
- Configured via Cluster `plugins` with `isWALArchiver: true`
- Stored in object storage: `s3://bucket/path/wals/<wal-segment>`
- Enables Point-in-Time Recovery (PITR) between full backups
- Archived every `archive_timeout` (default: 5 minutes)

## Retention Management

Backup retention is controlled by **ObjectStore CRD `retentionPolicy`**, not Backup/ScheduledBackup.

- Old backups automatically deleted from object storage
- Backup resources in Kubernetes deleted based on `backupOwnerReference`
- At least one backup always retained regardless of age
- Retention policy applies to base backups and associated WAL files

## Monitoring Backup Status

### Check Backup Success
```bash
kubectl get backups -n default
kubectl describe backup postgres-app-backup-20260103 -n default
```

### Check Scheduled Backup Status
```bash
kubectl get scheduledbackups -n default
kubectl describe scheduledbackup postgres-app-daily-backup -n default
```

## Common Patterns

### Development: Manual Backups Only
```yaml
# No ScheduledBackup - trigger backups manually as needed
apiVersion: postgresql.cnpg.io/v1
kind: Backup
metadata:
  name: postgres-app-manual-20260103
spec:
  method: plugin
  pluginConfiguration:
    name: barman-cloud.cloudnative-pg.io
    parameters:
      barmanObjectName: minio-dev
  cluster:
    name: postgres-app
```

### Staging: Daily Backups
```yaml
apiVersion: postgresql.cnpg.io/v1
kind: ScheduledBackup
metadata:
  name: postgres-app-daily
spec:
  schedule: "0 2 * * *"  # Daily at 2 AM
  method: plugin
  pluginConfiguration:
    name: barman-cloud.cloudnative-pg.io
    parameters:
      barmanObjectName: s3-staging
  cluster:
    name: postgres-app
  immediate: true  # Backup immediately on creation
```

### Production: Multiple Backups Per Day
```yaml
apiVersion: postgresql.cnpg.io/v1
kind: ScheduledBackup
metadata:
  name: postgres-app-frequent
spec:
  schedule: "0 */6 * * *"  # Every 6 hours
  method: plugin
  pluginConfiguration:
    name: barman-cloud.cloudnative-pg.io
    parameters:
      barmanObjectName: s3-prod
  cluster:
    name: postgres-app
  target: prefer-standby
  backupOwnerReference: cluster  # Backups deleted when cluster deleted
```

### Pre-Upgrade Backup
```yaml
apiVersion: postgresql.cnpg.io/v1
kind: Backup
metadata:
  name: postgres-app-pre-upgrade-20260103
  labels:
    purpose: pre-upgrade
    version: "16.0"
spec:
  method: plugin
  pluginConfiguration:
    name: barman-cloud.cloudnative-pg.io
    parameters:
      barmanObjectName: s3-prod
  cluster:
    name: postgres-app
  target: primary  # Ensure consistent snapshot from primary
```

## Validation Rules

- `method` must be `plugin` for Barman Cloud Plugin
- `pluginConfiguration.name` must be `barman-cloud.cloudnative-pg.io`
- `pluginConfiguration.parameters.barmanObjectName` must reference existing ObjectStore CRD
- `cluster.name` must reference existing Cluster in same namespace
- `schedule` must be valid cron expression (ScheduledBackup only)
- `target` must be `primary` or `prefer-standby`

## Troubleshooting

### Backup Stuck in "pending"
- Check cluster is healthy: `kubectl get cluster postgres-app`
- Verify ObjectStore CRD exists: `kubectl get objectstore minio-dev`
- Check operator logs: `kubectl logs -n cnpg-system deployment/cnpg-controller-manager`

### Backup Failed
- Describe backup: `kubectl describe backup <backup-name>`
- Check error message in status.error field
- Common issues:
  - Object storage credentials invalid
  - Network connectivity to S3 endpoint
  - Insufficient disk space on PostgreSQL pod
  - Barman Cloud Plugin not installed

### Scheduled Backup Not Triggering
- Verify schedule is not suspended: `spec.suspend: false`
- Check cron expression is valid
- Ensure operator has permissions to create Backup resources
- Review ScheduledBackup status: `kubectl describe scheduledbackup <name>`
